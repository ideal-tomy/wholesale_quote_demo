# このデモについて

## 1. 想定利用者

電材・機械部品卸の決裁者（50代・中間管理職を想定）。稟議を通す立場。画面上の利用者は営業・受注の担当者。

## 2. 現在の業務

得意先からの型番・在庫の問い合わせはメールで届く。在庫表、型番マスタ、掛け率は別の場所にある。担当者は探して、聞いて、文を書いて返す。確認の内容はメールとExcelと、詳しい人の頭の中に閉じる。

## 3. 困っていること

探す・聞く・文を書く、に時間が取られ、返す判断や得意先との関係に時間が残らない。確認を急ぐと数量や廃番の見落としが起きやすい。確認が人の頭に閉じるため、回数をこなしても会社に跡が残らず、いつもの問い合わせへの準備や、その先の予測・自動化の話に進めない。

## 4. このデモで体験できること

問い合わせを開くと、確認結果と返信下書きが並んでいる。根拠の表まで進んで数字を見てから、下書きのまま返すか直して返すかを担当者が決める。

## 5. 実装済み機能

- 問い合わせ一覧と詳細
- 確認結果、根拠（在庫表・型番マスタ・掛け率）
- 返信下書きの編集と確定（送信しない）
- 右ドロワーの追加確認（チップ）
- 在庫・得意先・見積の参照画面（体験の本筋ではない）

## 6. デモの体験順

`/desk` で3手 → 必要なら `/lp`

## 7. LPで伝えること

全体: 問い合わせの確認を先に進め、返す内容は担当者が決める。探す・聞く・書く時間を、得意先に何を返すかを考える時間に回す。対応の記録が残ると、よくある問い合わせへの準備や、その先の自動化を検討できる。

主役: 確認した内容が残ると、次の改善に使える、という気づき。いまのデモが予測や自動返信をする、とは書かない。

伝えないこと: 需要予測、自動返信、在庫引当、価格の自動確定。運送デモの「人数が増えたとき」「変わらないこと／変わること」。

## 8. 使用する画面

- 画面1: 問い合わせ机（在庫確認の1件。確認結果と返信下書き）
- 画面2: 在庫表（該当行）※根拠まで進めることの補助

## 9. LP → デモの導線

- LPヘッダー: 「デモに戻る」（ボタン。これだけ）
- クロージング: 「デモを続ける」。戻ったら、確認結果のあとに担当者が何を判断しているかを見る

デモ → LP:

- デスク右上の文字リンク「詳しい説明」
- サイドバーに「この画面の意味」「確認する」は置かない
